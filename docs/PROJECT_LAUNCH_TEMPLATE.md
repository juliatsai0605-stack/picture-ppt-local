# GitHub 專案展示發布標準流程（可沿用於下一個專案）

## A. 專案資料（每個新專案先填）

- 專案名稱：
- 一句話用途：
- 使用者與系統要求：
- GitHub Repository：
- Releases 下載網址：
- 核實的實際軟體截圖：
- 實際操作影片 URL：
- 授權條款與第三方元件 NOTICE：
- 資安與使用限制：
- 主要操作步驟（最多五步）：

## B. 預設網站資訊架構

1. Hero：一句話價值、免費下載、查看教學。
2. 功能亮點：最多三點，不誇大已驗收能力。
3. 操作影片：45–75 秒真實操作錄影；無影片時明確註記準備中。
4. 操作指南：下載→安裝／解壓縮→啟動→操作→輸出。
5. FAQ：相容性、限制、隱私、授權及錯誤處理。
6. Footer：GitHub、Releases、授權及聯絡方式（可省略個資）。

## C. GitHub Pages 發布

- 靜態網站存放 `docs/index.html`。
- 若為公開儲存庫，至 Settings → Pages，選 Deploy from a branch、main、/docs，儲存。
- 等候 GitHub 完成部署後，開啟 Pages 顯示的實際網址，檢查 200、版面、功能及連結。
- 專案首頁 README 放入網站入口和 Releases 入口。
- 後續專案可複製網站版型，再替換名稱、文字、顏色、影片、下載 URL。

## D. 發布驗收

- 桌機與手機均不溢出版面。
- 所有按鈕有作用，連結均指向正確專案。
- 不會將示意圖片說成真實截圖，不會將未錄製影片說成已有影片。
- README、版本號及網站下載按鈕一致。
- 影片示範從頭到尾可重現、無敏感資料、字幕正確。
- 「已公開儲存庫」與「已成功開通 Pages」分別驗證，不混為一談。

## E. 維護原則

- 原始程式與網站分離；頁面變更不影響主程式。
- 不要求每個專案都做影片，簡單工具以短操作片為主。
- 預設靜態託管，避免後端部署費用；不連接廣告、追蹤碼、付款服務。
- 任何新版本只需同步 README、網站特色、下載 URL 及示範影片。
